1. **Research Agent** (`src/lib/research-agent.server.ts` + `.functions.ts`) — calls Abacus.AI's real chat API (**note for future reference: their legacy `api.abacus.ai/api/v0/evaluatePrompt` endpoint now redirects callers to `POST https://routellm.abacus.ai/v1/chat/completions`, Bearer auth, model `route-llm`**) and, only on genuine success, inserts a real proposal into `proposals` as `pending`, submitted_by "Abacus.AI Research Agent." "Run research agent" button on the Agent Board.
2. **Critic Agent** (`src/lib/critic-agent.server.ts` + `.functions.ts`, added after Eric asked for more agent types) — takes a `proposal_id`, sends the full proposal to Abacus.AI with a genuinely adversarial system prompt (told explicitly not to rubber-stamp *and* not to manufacture concerns — free to honestly return `verdict: "no major issues"`), and on a parseable response inserts a row into a new `proposal_reviews` table (proposal_id, reviewer, verdict, critique). A DB trigger auto-logs the review to `activity_feed` so the critic shows up correctly on the Agent Board. "Review" button per pending proposal on the Proposals page, any submitter — shows all reviews newest-first with an amber "Flagged" badge vs. neutral "No major issues."

Both agents share the same honest-failure contract: any HTTP error, timeout, empty response, unparseable JSON, or failed insert throws and writes nothing — no fabricated proposal or review can land in the queue either way. Not yet tested end-to-end by Eric (his next step): run the Research Agent, then Review its output with the Critic, and see both show up together on a real proposal.

## Key decisions so far

- **Governance:** a board-meeting model with Eric holding unconditional veto on any real spend, external action, or new recurring commitment. Full detail in the plan doc §5.
- **Sub-agent hiring/firing:** delegated to a budget envelope + Hiring Committee (doesn't need board approval), with Eric retaining a standing right to hire/fire directly at any time, independent of the meeting cadence.
- **Financial recordkeeping:** a Controller/Bookkeeper agent role logs revenue/expense events with tax-relevant metadata as they happen — organizes records for a real accountant, does not replace one.
- **Ambition:** full self-funding autonomy is the long-term goal, reached only through the phased roadmap (§7) — currently at Phase 0, nothing built yet.
- **Product direction:** open-ended — agents research and decide what to build/sell, not a fixed product line.
